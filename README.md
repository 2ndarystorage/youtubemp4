# おうち動画保存 — Mac mini / iPhone 自宅Wi-Fi版

YouTubeの単体動画URLをiPhoneから送り、Macでyt-dlp / FFmpegを使ってMP4を作成する個人用Webアプリです。クラウドへの公開やポート開放は不要です。

## 初回準備（Macで行う）

1. ZIPを展開し、`local-video`フォルダーを「書類」などに置きます。
2. Homebrewが未導入なら https://brew.sh/ja/ の公式手順で導入します。
3. ターミナルを開き、`cd `（末尾に半角スペース）と入力し、このフォルダーをウィンドウへドラッグしてEnterを押します。
4. 次のコマンドを実行します。

```bash
bash setup.command
```

Homebrew経由でPython、yt-dlp、FFmpeg、Denoを導入します。初回は時間がかかり、Macのパスワードを求められる場合があります。上記のツール本体やライセンスはこのZIPには含みません。

## 毎回の起動

同じフォルダーで次を実行します。

```bash
bash start.command
```

ターミナルに接続キー付きURLが表示されます。Macの「システム設定 → Wi-Fi → 接続中のネットワークの詳細 → TCP/IP」で確認したIPv4アドレスに一致するURLを、同じWi-FiのiPhoneのSafariで開いてください。`127.0.0.1` はMac自身で確認するときだけ使います。URLは起動のたびに変わります。

例：`http://192.168.1.20:8765/?key=起動時に表示された文字列`

Macのファイアウォールで尋ねられた場合はPythonの着信接続を許可します。接続できない場合、iPhoneがゲストWi-Fiに接続していないか、ルーターの端末間通信禁止が有効でないかを確認してください。

## iPhoneでの使い方

1. YouTubeアプリの「共有 → リンクをコピー」でURLをコピーします。
2. 専用ページへ貼り付け、360p / 720p / 1080pから画質の上限を選びます。
3. 「Macで取得を開始」を押します。
4. 「完了」後に「MP4を保存」を押し、Safariのダウンロード確認が表示されたら許可します。
5. 「ファイル」アプリのダウンロード先で開きます。保存先はSafariのダウンロード設定に従います。

必要なら「ファイル」で動画を開き、「共有 → ビデオを保存」で写真アプリへコピーします。OSや動画の条件により表示が異なる場合があります。

ページを閉じてもMac側の処理は続きます。Macをシャットダウンすると停止します。起動中はcaffeinateでアイドルスリープを抑止します。終了はターミナルでControl+Cです。

## 機能と制限

- 単体の通常動画、Shorts、配信終了後の動画URLを受け付けます。プレイリストは取得しません。
- 最大2時間。配信中のライブは除外します。待機キューは最大20件です。
- iPhoneとの互換性を考慮してH.264映像とAAC音声のMP4を選択し、必要な場合は結合します。常に再エンコードする方式ではありません。指定上限以下の対応形式が提供されていない場合は失敗します。
- ダウンローダーに1ファイル2GB上限を指定していますが、これはMac全体の使用容量の上限ではありません。映像・音声・一時ファイルの合計は2GBを超える場合があります。
- 開始前に保存先SSDの空き容量が3GiB以上あるかを確認します。処理中の容量を保証するものではありません。
- 取得中の進捗は映像・音声ごとにリセットされます。結合はログ表示で、全体の残り時間を保証しません。
- Macにも `/Volumes/M2NVMe/YouTubeMP4/ジョブID/video.mp4` が残ります。削除は停止後に該当ジョブのフォルダーごとFinderで行ってください。失敗時の一時データも同じ場所です。
- 完了履歴は再起動後も読み込みます。中断ジョブは自動再開せず、再登録が必要です。
- YouTubeログイン、Cookie取り込み、有料・非公開動画、アクセス制限の回避は実装していません。公開動画でもYouTube側の制限により取得できない場合があります。
- iPhoneのネイティブアプリではなく、ブラウザで使うWebアプリです。共有シートから直接送信する拡張やQRコードは未実装です。

## 接続について

接続キーが分かる端末は操作・保存できます。キー付きURLを他人へ渡さないでください。サーバーはMacの全IPv4インターフェースの8765番で待ち受けます。自宅LAN向けのHTTP接続で、通信は暗号化されません。ルーターのポート開放・公開トンネルを設定せず、信頼できる自宅Wi-Fiで使ってください。macOSのインターネット共有やVPN経由のアクセス制限はこのアプリ自体では設定しません。

## 取得に失敗する場合

エラーは画面と `/Volumes/M2NVMe/YouTubeMP4/ジョブID/process.log` に残ります。YouTube側の変更に対応するため、まず停止して次を実行してください。

```bash
brew update
brew upgrade yt-dlp deno ffmpeg
bash start.command
```

更新後もログイン要求やHTTP 403などが出る動画は取得できない場合があります。成功を保証するものではありません。

## 利用条件と一次資料

第三者の公開動画でも、公開されていることや個人利用であることだけではYouTubeによる取得許可を意味しません。権利と利用条件を確認して使ってください。

- YouTube利用規約：https://www.youtube.com/static?template=terms
- yt-dlp公式（導入・依存関係・オプション）：https://github.com/yt-dlp/yt-dlp
- FFmpeg公式：https://ffmpeg.org/
- Homebrew公式：https://brew.sh/ja/

## 検証範囲

作成環境でPython構文、URL検証、認証、ジョブ受付、ファイル保存応答を自動確認しました。YouTube実動画の取得、Apple Silicon実機、iPhone Safari、macOSのファイアウォールは未検証です。Mac miniへのインストールと実機確認が次の工程です。


## 外付けSSDへの保存（今回の変更）

標準保存先は `/Volumes/M2NVMe/YouTubeMP4` です。M2NVMeを接続してから起動してください。SSDのマウントを確認してからフォルダーを自動作成します。動画・結合前の映像と音声・処理ログ・履歴をSSDに保存し、3GiB（約3.22GB）の空き容量もSSD側で判定します。起動時に保存先と空き容量を表示します。

SSD未接続時は起動を止めます。起動後も保存先への書き込み前とジョブ受付・処理開始時に接続を確認し、内蔵ディスクのdownloadsへ切り替えません。処理中にSSDを抜くと取得に失敗し、一時ファイルが残る可能性があります。再接続してから再登録してください。

既存の内蔵ディスク上のdownloadsは自動移動・削除しません。新しい保存先の履歴だけを表示します。Python等の実行環境とアプリ本体は元の場所に残ります。

更新は、起動中のターミナルでControl+Cを押してから、このリポジトリのフォルダーで実行します。

```bash
git pull --ff-only
bash start.command
```

別の保存先を一時指定する場合：

```bash
VIDEO_SAVER_DIR="/Volumes/別のSSD/YouTubeMP4" bash start.command
```

Linux上で既存テスト4件と保存先関連テスト2件を確認しています。Mac実機のSSDへの実際の書き込み・取り外し試験は未実施です。


## Address already in use（8765番ポートの競合）

`OSError: [Errno 48] Address already in use` は、他のプロセスが同じポートを使用中という意味です。SSDの空き容量とは別の問題です。

現在は8765〜8774番の順で起動を試み、実際に使うポートを含む接続URLを表示します。他のアプリや先に起動したプロセスは停止しません。更新後は新しいターミナルに表示されたURLで開き直してください。

別の開始ポートを指定する場合：

```bash
VIDEO_SAVER_PORT=8800 bash start.command
```

使用中のプロセスを確認するだけなら、Macで `lsof -nP -iTCP:8765 -sTCP:LISTEN` を実行します。古いサーバーを開いているターミナルが分かる場合は、そこでControl+Cで停止できます。

検証：既存6件に加え、ポートを実際に占有した状態で別ポートのHTTPページ応答が成功すること、候補がすべて使用中ならエラーになることを確認しました（計8件）。Mac実機での起動は未検証です。
